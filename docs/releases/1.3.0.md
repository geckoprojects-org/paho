First release of the Gecko build of the [Eclipse Paho Java client](https://github.com/eclipse-paho/paho.mqtt.java),
based on upstream `develop` (1.2.5 plus later fixes). Same packages, bundle symbolic names and API as
upstream (Java 8 or newer), own Maven coordinates:

```xml
<dependency>
    <groupId>org.geckoprojects.paho</groupId>
    <artifactId>org.eclipse.paho.client.mqttv3</artifactId> <!-- or org.eclipse.paho.mqttv5.client -->
    <version>1.3.0</version>
</dependency>
```

The artifacts are published on [Maven Central](https://central.sonatype.com/namespace/org.geckoprojects.paho);
the files attached here are the same jars, poms and GPG signatures, downloaded from there.

## What is different from upstream 1.2.5

- **Reconnect** (v3, v5): a connect attempt without CONNACK times out; the reconnect cycle no longer
  ends silently, stops on `disconnect()`/`close()`, is kept per client and follows the monotonic
  clock; subscriptions are restored after a reconnect without session (`automaticResubscribe`).
- **Delivery** (v3, v5): no more "Too many publishes in progress" for sequential QoS 1/2 publishes;
  a message without callback or listener is acknowledged instead of redelivered forever; v5 topic
  aliases, subscription identifiers and shared subscriptions work as specified (v3: shared
  subscriptions too).
- **Security** (v3, v5): inbound packets and WebSocket frames are limited (1 MiB by default) and
  checked before allocation; no passwords in the log; owner-only file persistence; a warning for
  credentials without TLS; random client ids.
- **Long-running devices** (v3, v5): no leaks of file descriptors, message IDs, listeners or stored
  messages; a bounded send queue (`maxQueuedMessages`); no wakeups of an idle client between
  keep-alive pings; an application `ScheduledExecutorService` replaces the timer threads.
- **WebSocket** (v3, v5): pings answered, fragmented messages reassembled.
- **OSGi and Java 16+**: the v5 bundle exports all API packages; broker host names with `_` work
  without reflection.

Every change has an issue in this repository. The full list, the **behaviour changes applications
may notice** and the security fixes with their CWEs are in
[docs/UPSTREAM.md](https://github.com/geckoprojects-org/paho/blob/v1.3.0/docs/UPSTREAM.md); the
[guide](https://github.com/geckoprojects-org/paho/blob/v1.3.0/docs/GUIDE.md) covers setup,
options and examples for desktop and embedded use.
